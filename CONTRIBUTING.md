# Contributing

Thank you for helping make this accurate. Corrections are more valuable than additions.

## Setup

```bash
pip install -e ".[dev]"
pytest
python tools/sync_diagrams.py --check
python tools/check_docs.py
```

Please run all three before opening a pull request. All must pass.

## The rules that keep this trustworthy

1. **Numbers come from code or from a citation.** If an article states a number, it is produced by `src/ie/` (and a test in `tests/test_article_numbers.py` checks the article text), or it is cited to a primary source with the claim it supports. Do not hand-compute.
2. **No invented benchmarks.** A measured result needs a JSON file in `labs/bench/results/` recording the GPU, driver, library versions, model, batch, context and seed. Arithmetic from datasheets is labelled a ceiling.
3. **Cite primary sources.** Prefer the original paper or the vendor datasheet over a blog post. Add the source to `papers.md` with the claim it supports.
4. **Explain why before how.** State the bottleneck an optimisation attacks before describing the mechanism.
5. **Keep units consistent.** Capacity is binary (GiB), bandwidth and FLOP/s are decimal. State a conversion once and stay in one system. Use `src/ie/units.py`.
6. **Match the terminology in `GLOSSARY.md`.** Add a term there when you introduce one.
7. **Punctuation.** Do not use em-dashes in prose. Use a comma, semicolon, colon or parentheses. `tools/check_docs.py` enforces this.

## Diagrams

Edit the Mermaid source in `diagrams/src/`, then run `python tools/sync_diagrams.py`. It rewrites every embedded copy and the gallery, so a diagram has exactly one source of truth. Never edit an embedded block by hand. Figures that plot data (`d04`, `d08`) are generated by scripts in `tools/` from the same library the articles use.

## Adding a lab

A lab is a small script in `labs/cpu/` that prints its result, uses `src/ie/` for every spec and model constant, and has a test. It must run without a GPU.
